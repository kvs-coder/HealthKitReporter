# 11. Risks and Technical Debt

| # | Risk / debt | Impact | Mitigation |
| :--- | :--- | :--- | :--- |
| R1 | **Contract coupling to the Flutter plugin.** The JSON shape is an untyped, cross-repo contract. | A library release ahead of the plugin breaks plugin users at runtime (ADR 0004). | Coordinated major releases; round-trip tests; publish the library only after the plugin release is ready. |
| R2 | **Store-dependent code is not unit-tested.** Tests use the public API only, and the test host has no HealthKit entitlement, so HealthKit returns errors and never data. The HK → payload mapping (harmonize decorators, payload HK initializers, factories, retrievers), the SI unit table, builder-based `saveWorkout`, background delivery and attachments are exercised only on their error paths. | Mapping regressions surface only in the Example app or on device; library coverage is 65.3 % instead of ~80 %. | Example app demos and simulator seeding for every writable type; manual check of read-only data on device. Revisit `@testable` mapping tests or an entitled, UI-automated integration target if mapping bugs slip through. |
| R3 | **Stored samples are found by `uuid`.** `delete(sample:)`, `addQuantity` / `addCategory` and `unrelateWorkoutEffort` look the stored HealthKit object up by the payload's `uuid` before acting (resolved in 4.0.0; before, they acted on fresh copies with new UUIDs). | A payload built in the app, or one whose `uuid` was dropped, matches nothing and completes with an error. | `save` reports the stored `uuid`; `copyWith` and `make(from:)` keep it, `copyWith(uuid:)` sets it. The Flutter plugin must send the `uuid` back. |
| R4 | **Silent sample skipping.** The internal `collect(results:)` drops samples that fail to convert. | A mapping bug can hide data without an error. | Consider reporting skipped counts if consumers need it; mapping is checked through the Example app (R2). |
| R5 | **Metadata quantity units are guessed.** `HKQuantity` does not expose its unit, so a read quantity is expressed in the first compatible unit of a fixed list (ADR 0002). | Unusual units come back converted. | Documented in ADR 0002; extend the list when a consumer needs another unit. |
| R6 | **HealthKit API growth.** Apple adds types and APIs every year; enums with ~240 / ~140 cases must track them. | Missing types, or unguarded use of new APIs. | Exhaustive switches, availability guards, one SI-unit source; the Example app authorizes every `allCases` type, so a new case shows up there. |
| R7 | **Legacy SwiftLint violations** are baselined in `.swiftlint.baseline`. | Old code does not meet current rules. | Only new violations fail CI; regenerate the baseline only when fixing legacy code. |
| R8 | **Coverage floor at 65.3 %**, lowered from 77.6 % in 4.0.0 (R2). | The gate no longer protects the mapping code. | Each test PR raises it to the new measured level; never lowered again without a recorded reason. |
| R9 | **No async/await API.** | Swift consumers wrap callbacks themselves. | Out of scope per ADR 0003; add for the whole API in one major release if needed. |
| R10 | **Health records need an Apple Account and a paid team.** Requesting clinical types starts Health's records flow, and the health-records entitlement needs a paid developer account. | Authorization including clinical types stalls on a fresh simulator; free teams can't sign the Example app with that entitlement. | Clinical types are requested separately from everything else; `supportsHealthRecords()` gates the clinical demos. |

The former risk "HealthKit types in the public API" is resolved in 4.0.0 (ADR 0005) and guarded by the
`no_public_healthkit_types` swiftlint rule; only Foundation types (`NSPredicate`, `NSSortDescriptor`) remain in
public signatures besides library types.
